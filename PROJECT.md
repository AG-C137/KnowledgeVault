# KnowledgeVault

## Назначение

KnowledgeVault — система для хранения и организации личной библиотеки знаний.

Проект позволяет сохранять материалы из различных источников в открытых форматах и работать с ними независимо от исходной платформы.

Основная задача — не создание новой базы знаний, а сохранение уже найденной и изученной информации.

---

# Основные требования

## 1. Локальное хранение

Основная копия библиотеки всегда находится у пользователя.

Облачные сервисы могут использоваться только для синхронизации и резервного копирования.

---

## 2. Открытые форматы

По возможности используются открытые и долговечные форматы:

* Markdown
* JSON
* JPEG / PNG / WEBP
* PDF (если невозможно сохранить иначе)

Файлы должны быть доступны без специализированного программного обеспечения.

---

## 3. Сохранение исходных данных

При импорте материала желательно сохранить:

* заголовок;
* автора;
* дату публикации;
* источник;
* основной текст;
* изображения;
* ссылки;
* доступные метаданные.

Преобразования не должны изменять смысл исходного материала.

---

## 4. Независимость от источников

Каждый источник реализуется отдельным модулем.

Например:

* Sponsr;
* Telegram;
* RSS;
* YouTube;
* книги;
* PDF;
* веб-сайты.

Поддержка нового источника не должна требовать изменения структуры библиотеки.

---

## 5. Простая структура

Библиотека должна оставаться понятной без специальных инструментов.

Пользователь должен иметь возможность открыть каталог и найти нужный документ вручную.

---

## 6. ИИ — дополнительный инструмент

Локальные языковые модели используются для поиска, анализа и навигации по библиотеке.

Они не заменяют сами документы.

---

## 7. Долговременное хранение

При выборе между удобством и надежностью предпочтение отдается надежности.

Желательно избегать решений, создающих зависимость от конкретных сервисов, платформ или облачных API.

---

# Что не является целью проекта

Проект не предназначен для:

* хранения единственной копии данных в облаке;
* работы только с одним источником;
* привязки к конкретной программе для заметок;
* зависимости от одной модели ИИ.

---

# Цель первой версии

Получить рабочую систему, которая позволяет:

* импортировать материалы из различных источников;
* сохранять их в единой структуре;
* выполнять поиск по библиотеке;
* использовать локальные модели ИИ для работы с сохраненными материалами.

# ARCHITECTURE.md

# Архитектура KnowledgeVault

## Архитектурные принципы

### Источники данных

KnowledgeVault не отвечает за получение данных.
KnowledgeVault импортирует знания, а не формат файлов. 

Получение данных осуществляется специализированными инструментами.

Примеры:

- sponsrdump
- yt-dlp
- calibre
- rss readers

KnowledgeVault работает только с локальным архивом.

---

### Разделение ответственности

Downloader:

- скачивает
- обновляет
- синхронизирует

KnowledgeVault:

- импортирует
- индексирует
- хранит
- связывает
- предоставляет поиск
- предоставляет интерфейс LLM

# Основные компоненты

## Источник (Source)

Источник — это внешний сервис или формат данных.

Например:

* Sponsr
* Telegram
* RSS
* EPUB
* PDF
* Web

Каждый источник независим от остальных.

---

## Импортёр (Importer)

Импортёр получает материалы из конкретного источника.

Он отвечает только за получение данных.

Импортёр не должен выполнять поиск, индексирование или анализ.

---

## Нормализация (Normalizer)

Материалы из разных источников приводятся к единому внутреннему представлению.

На этом этапе формируются:

* текст;
* метаданные;
* список изображений;
* ссылки;
* вложения.

После нормализации дальнейшая обработка не зависит от исходного источника.

---

## Библиотека (Library)

Основное хранилище документов.

Содержит:

* Markdown-документы;
* изображения;
* вложения;
* служебные файлы.

Структура библиотеки должна быть понятной без использования специальных программ.

---

## Индексатор (Indexer)

Создает поисковый индекс библиотеки.

Индекс не является основным хранилищем данных.

При необходимости он может быть полностью пересоздан из библиотеки.

---

## Семантический поиск

По желанию пользователя создаются эмбеддинги документов.

Они используются для семантического поиска и работы локальных языковых моделей.

Эмбеддинги являются производными данными и могут быть пересозданы.

---

## Локальная LLM

Использует библиотеку и индекс для:

* поиска информации;
* ответов на вопросы;
* навигации по документам;
* анализа материалов.

Модель не изменяет исходные документы.

---

# Основные принципы

* библиотека является главным источником данных;
* все остальные компоненты могут быть пересозданы;
* каждый компонент выполняет только одну задачу;
* источники независимы друг от друга;
* новые источники подключаются без изменения существующей структуры библиотеки.

#STORAGE.md

одна архитектурная идея

`
Оригиналы
    ↓
Документы
    ↓
Производные данные`

Например:

` Sponsr HTML
        ↓

Markdown
        ↓

SQLite
Embeddings
Кэш
Поисковый индекс `

То есть:

* Markdown — это "истина" (каноническое представление).
* SQLite — производная.
* Эмбеддинги — производные.
* Поисковый индекс — производный.
* Кэш — производный.

Это очень сильное архитектурное правило. Если завтра что-то сломалось или поменялась модель эмбеддингов, мы просто удаляем производные данные и пересоздаем их. Канонические документы остаются нетронутыми.
